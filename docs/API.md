# 本地后端 API · v1

运行环境：Node.js 22 或更高版本。首次运行 `npm ci`，之后 `npm start` 自动构建前端并监听 `http://127.0.0.1:4317`。仅限本机，尚不支持局域网、账号或多人访问。

环境变量：`PORT`、`HARMONICA_LIBRARY`（Markdown 乐谱目录）、`HARMONICA_VAULT`（附件搜索根目录）、`HARMONICA_DATA`（新谱数据目录，默认项目下 data）。默认库指向用户现有 F 盘口琴乐谱，附件搜索根目录为软件笔记。

| 请求                    | 用途                                           |
| ----------------------- | ---------------------------------------------- |
| GET /api/health         | 服务状态、库数量和读取异常                     |
| GET /api/launcher       | 书签只读快速就绪检查，不返回路径或谱面         |
| GET /api/library        | 原谱列表：id、title、category                  |
| GET /api/original?id=0  | 原 Markdown 和可访问的图片 URL                 |
| GET /api/image?id=0&n=0 | 该原谱引用的第 n 张图片                        |
| GET /api/scores         | 所有新建谱                                     |
| POST /api/scores        | 创建新谱或按 revision 校验后覆盖；临时文件原子替换 |
| DELETE /api/scores/:id  | 将新谱移入 data/trash；不删除原有 Markdown     |

GET `/api/health`另返回`app: "harmonica-studio"`与绝对`dataDirectory`，供本机启动器识别服务及曲库，避免复用错误端口；原有字段保留。

原谱只读。库在启动时扫描，增加文件后需重启；原谱 id 仅在当前扫描内有效，不应用作永久外键。图片首次访问时搜索附件，重名图片返回错误而非猜测。当前支持 Obsidian `![[图片.png|宽度]]` 引用，不包含普通 Markdown 图片语法。

旧稿可保留为 `archived: true`，并可带 `primaryScoreId`、`archivedAt`、`archiveReason`。保存接口保留这些元数据，不移动或删除音符；前端在「归档版本」筛选中显示，可恢复回普通列表。GET 仍返回所有新谱，前端负责过滤归档及默认列表中已转谱的重复原图入口。

## 新谱格式

```json
{
  "version": 1,
  "id": "unique-score-id",
  "title": "新乐谱",
  "key": "C",
  "bpm": 90,
  "notes": [
    { "type": "note", "degree": 1, "octave": 0, "sharp": false, "duration": 1 },
    {
      "type": "note",
      "degree": 2,
      "octave": 1,
      "sharp": true,
      "duration": 1.375
    },
    {
      "type": "note",
      "degree": 0,
      "octave": 0,
      "sharp": false,
      "duration": 0.5
    },
    { "type": "break" }
  ]
}
```

`degree` 为 0–7，其中 0 为休止；`octave` 为 -2、-1、0、1、2，重复同类括号 `((1))` / `[[1]]` 表示倍低 / 倍高音，混用高低音括号仍拒绝；`duration` 是相对拍长，范围 0.125–8，可小数微调；真实秒数为 duration × 60 / bpm。换行不自动加入停顿。`{"type":"space"}` 仅作视觉分组，不占播放时长。C 调中音 1 暂定 C4，A 调中音 1 暂定 A3，推键暂按升半音。以上可在体验后调整，不代表已对用户乐器完成校准。

可选字段：`category`（100 字内）、`favorite`（布尔）、`status`（未练习 / 练习中 / 熟练）、`durationScale`（整体音长倍率，0.25–2，缺省为 1）。设置倍率后，真实秒数为 duration × durationScale × 60 / bpm；原始音长与数字字号不变，休止也同比缩放。服务器在保存成功后返回并写入 `updatedAt`。同 ID 保存串行执行，覆盖前保留 `.json.bak`；GET 列表排除备份与回收目录。

界面只有一个「播放速度」，显示有效 BPM：`bpm / (durationScale ?? 1)`。旧谱载入不改写，原播放快慢保持一致；用户调速时将有效速度写入 bpm，并移除普通范围内的 durationScale。为兼容有效速度超出30–240的旧谱，保留必要的存储倍率，但界面始终只有一个速度。预设60/90/120/160与滑杆操作同一数值，不再叠加倍速。

有音高的音符另可带 `tailHold`（0–4，缺省为 0），用于单独保留段尾延长量：该音实际秒数为 `(duration + tailHold) × durationScale × 60 / bpm`，取消延长时移除此字段即可恢复原始时值。段后留白仍用 `degree: 0` 的休止表示，可在原 JSON 格式中保存；界面显示为灰色「停」。编辑模式按空格直接插入四分休止（duration:1），存在选区时在选区末尾追加而不替换选中内容。「不停」选项已移除。旧分组空格显示为「·」并继续不占拍，选中设置正时值可原位转为休止，删除使用删除键。应用内 JSON 复制、保存和导出保留延长量，纯数字文本不能表示这一附加信息。

模型转谱输出此 JSON 可通过前端导入（创建新 ID），或直接调用保存接口（覆盖同 ID 时必须带读取时的 revision）。目前没有接入模型、OCR 或自动推断时值。纯文本导入默认每音 1 拍，拒绝错配括号；空白不会被猜成音长。旧笔记正文以纯文本显示，不执行原文 HTML。

## 保存版本校验

行重复为可选的音符字段 `repeat: 2..8`（整数，总遍数含第一次）。前端对本行所有音符统一设置，取消时删除字段，旧谱缺省为一遍，version仍为1。不复制notes；播放时间轴逐行展开，休止与尾音一同重复，只有完整进入播放范围的行才展开。删首音仍保留标记；拆行后两行继承，合行取现存较大次数，可在行尾重新设置。JSON导入、导出、内部复制与草稿保留；纯数字文本不携带此元数据。版本冲突核对也显示行重复次数。

GET `/api/scores` 为每条记录附加 `revision`，值为磁盘原始文件内容的 SHA-256。覆盖时在 JSON 请求体中原样携带读取时的 `revision`；成功响应返回新的 `revision` 与 `updatedAt`。`revision` 不写入乐谱文件，不需要迁移原曲库。新 ID 不带 revision；导入会移除此字段并创建新 ID。

同 ID 的读取校验、备份与写入在服务写队列内执行。缺少 revision 的旧稿可用原有 updatedAt 自动兼容：服务只从已记录的保存指纹中找唯一对应版本，并要求该指纹与当前磁盘内容完全一致，才留bak后更新同一ID。来源记录在 `data/.protection/versions.jsonl`，仅存ID、原保存时间及哈希，不包含音符；跨服务重启保留。没有可信来源或同时间对应多个内容指纹时返回428，由界面提供一次核对；来源明确但磁盘已变化返回409。携带旧时间的已删除记录不能直接重建。失败不改目标文件及 `.bak`。

历史数据可通过 `node scripts/seed-legacy-versions.mjs <曲库目录> <快照内相对曲库路径> <已知历史快照目录...>` 从已有manifest.json和SHA-256校验过的快照初始化指纹，初始化不写乐谱文件。服务不会把启动时读取的当前文件自动当作旧稿基础；不要用新拷贝的当前曲库冒充历史快照。内容哈希仍检测未更新updatedAt的外部改动，但不提供外部工具并发写入的跨进程锁。`/api/health`的legacyAutoSave为true表示支持兼容。

音符的可选 `performance` 字段为 `"chorus"`（副歌增强）或 `"calm"`（平缓收敛）；缺省时自动估计视觉强度。只影响练习模式演出，不改变音高、时值或播放声音。标记附着在音符上，JSON 导入导出、保存、复制与撤销保留；纯数字文本不能携带标记。休止可以保留标记，但不触发音头爆点。版本号仍为 1，旧谱无需迁移。

## 后续前端约定

- 正式前端已接入保存与播放；设计档案只用于保留早期提案。
- 前端布局提案见 `docs/design/harmonica-studio.html`。无右侧原谱对照栏；当前绿色配色未定稿。
- 播放高亮与装饰音符特效分开处理；特效可关闭、保存偏好，首次访问尊重减少动态效果设置。
- 自定义快捷键在谱面获得焦点时生效，避免拦截全局浏览器操作。
- Z / C 默认按标准时值步进，Shift 或「含附点」加入附点档位；导入可保留任意有效时值，不采用按住计时。
- 播放调度以音频时钟为准，视觉特效跟随播放位置，不能反过来影响节奏。
- 已接入本地口琴采样与合成音；来源与测试边界见 `docs/SOUNDFONTS.md`。
- 批量转谱若使用子代理，仅使用 Luna 或 GPT-6.1-sol medium；转谱结果需人工校对。

## 当前限制

同 ID 保存会拒绝旧版本覆盖，不自动合并冲突；只保留上一次保存备份，删除项进入本机回收目录。附件目录首次扫描可能较慢。原谱和附件不复制进仓库。JSON 上传界面和键盘编辑已实现；自动转谱、音频识谱不在第一版中。
## 书签快速就绪检查（2026-10-24）

`GET /api/launcher` 返回 `{ "ok": true, "app": "harmonica-studio", "version": 1 }`，检查当前服务的曲库与最新launcher.json一致、首页/app.js存在且非空。配置或资源未就绪返回503，曲库不匹配返回409。仅本机Host可访问；此GET允许Origin:null的本地文件书签读取无敏感就绪信息，不返回实际目录/曲谱。其他来源、POST和其他API仍保持原有同源限制。响应不缓存。
